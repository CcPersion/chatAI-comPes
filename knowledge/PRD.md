# PRD: local-ai-companion-v2

## 项目背景与目标

### 背景

- 旧版 v1 采用 Unreal Engine + MetaHuman + Pixel Streaming 重型 3D 路线，学习、资产、安装与调试成本过高，卡在约 30% 无法落地。
- 2026-08-03 零度解说发布一套已验证可运行的本地 wav2lip 数字人全流程方案（speech-to-speech）。v2 以此方案为技术路线，技术栈已固定，不再做技术选型。
- 目标硬件：RTX 5060 Ti 16GB 显存 / 16GB 系统内存 / SSD / Windows + WSL2 Ubuntu 24.04。

### 一句话描述

Windows 本机运行、浏览器访问的本地真人 AI 语音伴侣：用户打开 `localhost:7860`，点击语音球说话，系统在 WSL2 内完成「语音识别 → 大模型对话 → 音色克隆语音合成 → wav2lip 实时口型」全链路，数字人画面通过 LiveTalking WebRTC 实时推送到浏览器，支持打断与断网使用。

### 与 v1 / 原始需求的差异

v2 在保留原始需求的用户价值与硬性约束（Web 端、本地推理、无云端、单用户单角色、页面简洁、写实女性、非预录视频）的前提下，替换底层技术路线：

| 能力 | v1 / 原始需求文档 | v2（零度方案，已固定） |
| --- | --- | --- |
| 网页前端 | React / Next.js | Gradio（speech-to-speech 自带，后续可升级） |
| 本地大模型 | Ollama + 中文开源模型 | llama.cpp + Qwen3（Windows 侧运行 server） |
| 语音识别 | SenseVoice | faster-whisper large-v3 |
| 语音合成 | CosyVoice | Qwen3-TTS 1.7B + 声音克隆 |
| 数字人视觉 | Unreal + MetaHuman + Pixel Streaming | ComfyUI + Wan2.2 生成 idle.mp4 底版 + wav2lip256 实时口型 + LiveTalking WebRTC |
| 运行环境 | 全 Windows / Unreal 工程 | WSL2 Ubuntu 24.04 跑 AI 链路 + Windows 侧 llama.cpp server |

### 目标

1. 在目标硬件（16GB 卡）上跑通完整本地语音对话闭环，浏览器可见数字人画面、语音球、聊天记录、输入框、麦克风与停止按钮。
2. 说话时口型实时跟随音频；支持用 5-15 秒参考音频克隆音色；支持中途打断。
3. 显存适配：16GB 卡默认使用 Qwen3-8B（约 6GB），总显存控制在约 14GB；14B 模型（约 9GB）标记为推荐配置，仅用于 24GB 卡。
4. 首次联网下载模型与依赖后，断网可完全离线运行。

### 分阶段里程碑（指导开发落地顺序，不改变功能范围）

- **M1 基础闭环**：一键启动，浏览器打开 `localhost:7860`，数字人待机画面 + 语音球 + 文字聊天可用，本地 llama.cpp 流式回复。
- **M2 语音闭环**：麦克风 → faster-whisper → LLM → Qwen3-TTS → 音频播放，语音球交互可用，文字兜底可用。
- **M3 真人感联动**：音色克隆、wav2lip256 实时口型、LiveTalking WebRTC 画面推送、打断与静音检测参数可调，连续三轮对话验收。

## 用户故事

### US-01: 一键启动即见数字人 (Priority: Must)

作为用户，我希望运行一键启动脚本后，浏览器打开 `localhost:7860` 即可看到数字人待机画面和语音球，不需要手动逐个启动服务。
验收点：启动后 60 秒内页面可访问；画面来自本地 wav2lip 链路，非预录循环视频。

### US-02: 语音对话完整闭环 (Priority: Must)

作为用户，我希望点击语音球说话后，系统能把我说的中文转成文本、让 AI 本地生成回复、用合成语音回答，并让数字人嘴型实时同步。
验收点：VAD → ASR → LLM → TTS → 播放 全链路本地完成；转写文本与回复文本正确显示在聊天记录；嘴型跟随音频。

### US-03: 音色克隆 (Priority: Must)

作为用户，我希望上传一段 5-15 秒的参考音频，让数字人用克隆出来的音色说话。
验收点：克隆后 TTS 输出音色与参考音频在听感上明显相似。

### US-04: 说话打断与停止 (Priority: Must)

作为用户，当 AI 正在说话时，我重新点击语音球说话或点击停止按钮，AI 应立即停止出声与闭嘴，转入倾听，新一轮回复不混入上一轮残留音频。
验收点：音频与嘴型在 500ms 内停止；新一轮无串音。

### US-05: 断网可用 (Priority: Must)

作为用户，我希望模型下载完成后，即使断网也能正常进行全部对话功能。
验收点：禁用网络后重复语音/文字对话仍完整可用。

### US-06: 文字聊天兜底 (Priority: Should)

作为用户，当语音识别失败或环境嘈杂时，我希望仍能用文字输入进行对话。
验收点：停用 ASR 后，文字输入仍可流式回复，语音输出按配置可选。

### US-07: 低首响延迟 (Priority: Should)

作为用户，我希望从我说完话到听到 AI 第一句语音的时间尽量短。
验收点：16GB 卡 + Qwen3-8B 目标配置下，首响延迟 P50 ≤ 2 秒、P95 ≤ 3 秒。

### US-08: 页面简洁不打扰 (Priority: Should)

作为用户，我希望页面只显示与对话相关的核心控件，不出现情绪面板、模型参数面板或调试面板。
验收点：页面仅含数字人画面、语音球、聊天记录、输入框、麦克风、停止按钮与连接状态提示。

### US-09: 参数可调 (Priority: Could)

作为高级用户，我希望通过配置文件调整 VAD 静音检测灵敏度、首响延迟相关参数等。
验收点：修改配置文件后参数生效且不破坏默认使用。

### US-10: 多用户 / 多角色 / 3D 升级 (Priority: Won't)

作为用户，我暂不需要多用户、多角色、全天候唤醒或 3D 真人升级，v2 不做这些。

## 功能范围

### 包含

- **Web 页面（Gradio 基础形态）**：数字人画面（页面背景/视觉中心）、语音球、聊天记录、文字输入框、发送按钮、麦克风按钮、停止按钮、本地服务连接状态提示、AI 文本流式展示。
- **语音对话链路**：浏览器/前端采集麦克风 → VAD 静音检测 → faster-whisper large-v3 中文识别 → llama.cpp + Qwen3 流式对话 → Qwen3-TTS 1.7B 合成并播放。
- **数字人视觉链路**：ComfyUI + Wan2.2 一次性生成 `idle.mp4` 底版视频 → wav2lip256 按实时音频驱动口型 → LiveTalking 经 WebRTC 将画面低延迟推送到浏览器。
- **音色克隆**：支持上传 5-15 秒参考音频，TTS 使用克隆音色。
- **打断能力**：用户重新说话或点击停止时，取消 LLM 后续流、TTS 队列、音频播放与说话状态；VAD 静音检测参数可调。
- **本地服务编排**：Bash (.sh) + Windows Batch (.bat) 一键启动/停止脚本，支持重复启停与端口清理。
- **显存预算管理**：默认加载 Qwen3-8B（约 6GB）适配 16GB 卡；支持切换到 Qwen3-14B（约 9GB，24GB 卡推荐配置）。
- **离线能力**：首次联网下载模型与依赖后，断网可运行。

### 不包含（v2 范围外）

- Unreal Engine / MetaHuman / Pixel Streaming 3D 数字人路线。
- 任何云端推理：OpenAI、D-ID、HeyGen 等付费接口。
- 多用户 / 多会话 / 多角色。
- 全天候免唤醒语音助手（v2 为「点击语音球说话」式交互）。
- 情绪可视化面板、模型参数面板、调试面板。
- 自定义 React/Next.js 前端（v2 用 Gradio，升级留待后续版本）。
- 高精度音素级嘴型、全身 3D 动作捕捉。
- 长期记忆 / 外部知识库（RAG） / 角色养成。
- 公网部署、移动端适配。
- 第三方付费或授权不清晰的商业资产。

## 验收标准

1. **一键启动**：运行启动脚本后，浏览器打开 `http://localhost:7860` 可见数字人待机画面与语音球；ASR / LLM / TTS / wav2lip / LiveTalking 各服务在 60 秒内就绪并显示连接状态。
2. **全链路语音对话**：用户点击语音球说一句中文，系统完成 VAD → ASR → LLM → TTS → 播放的完整闭环；页面正确显示转写文本与 AI 回复文本，且回复文本为流式展示。
3. **本地无外传**：断网状态下重复进行语音对话，全部功能仍可用；日志与网络检查确认除本机服务外无任何请求发往外部推理接口。
4. **首响延迟**：目标配置（16GB 卡 + Qwen3-8B）下，从用户说完话到听到 AI 第一句音频的时间 P50 ≤ 2 秒、P95 ≤ 3 秒。
5. **音色克隆**：使用 5-15 秒参考音频克隆后，TTS 输出音色与参考音频在听感上明显相似（3 人主观盲评中至少 2 人辨识一致）。
6. **打断**：AI 说话中途，用户重新点击语音球说话或点击停止按钮，音频与嘴型在 500ms 内停止；随后开启的新一轮对话无上一轮残留音频与残留状态。
7. **显存预算与失败提示**：16GB 卡 + 8B 配置下，运行全程总显存占用 ≤ 14GB；若发生显存/内存不足，系统输出可理解的错误提示而非无响应或静默失败，且进程可重启恢复。
8. **文字兜底**：停用 ASR 服务后，文字输入对话仍可完整工作（本地 LLM 流式回复，TTS 按配置可选）。
9. **页面简洁**：页面仅包含数字人画面、语音球、聊天记录、输入框、麦克风、停止按钮与连接状态；不出现情绪面板、模型参数面板或调试面板。
10. **连续对话稳定性**：连续完成至少 3 轮语音对话（含 1 次中途打断），全程不崩溃、不卡死、不串音、不串状态。

## 非功能需求

### 性能

- **首响延迟**：目标配置（8B）下 P50 ≤ 2 秒、P95 ≤ 3 秒（从用户说完到听到 AI 首句）。
- **显存预算**：16GB 卡 + 8B 配置总显存占用 ≤ 14GB；24GB 卡 + 14B 配置 ≤ 17GB。
- **口型同步**：wav2lip256 推理需满足实时速率，口型与音频偏差 ≤ 300ms。
- **画面规格**：数字人目标 720p / 30 FPS；WebRTC 推送延迟可感知但 ≤ 1 秒。
- **系统内存**：MVP 阶段可运行于 16GB 系统内存，但不保证同时全开高画质与全部组件；长期稳定建议 32GB。
- **启动就绪**：一键启动脚本须在服务就绪后给出明确就绪信号，避免用户误判页面未加载完成。

### 安全

- **100% 本地运行**：所有推理在本机（WSL2 + Windows）完成，不调用任何云端推理 API。
- **数据不出本机**：录音、转写文本、对话记录、参考音频仅存本地，不上传任何远程服务。
- **端口封闭**：服务仅绑定 `127.0.0.1`，不对外网开放端口。
- **可信来源**：模型与依赖首次从官方/可信源（HuggingFace、官方仓库等）下载，并校验哈希；无远程遥测。

### 兼容性

- **操作系统**：Windows 10/11 + WSL2 Ubuntu 24.04；llama.cpp server 运行于 Windows 侧。
- **显卡与驱动**：NVIDIA RTX 5060 Ti 16GB，需 CUDA 与 WSL2 GPU 透传可用。
- **浏览器**：Chrome / Edge 最新稳定版（支持 WebRTC / WebAudio）。
- **启停脚本**：提供 `.sh` 与 `.bat` 一键启动/停止，可重复运行且清理残留进程与端口占用。

## 已知限制

- **显存处于上限边缘**：14B + 全套组件同时常驻可能 OOM；默认使用 8B，必要时串行加载组件或关闭未用模型。
- **系统内存偏紧**：16GB 内存下 LLM 推理与 TTS 同时进行时可能吃紧，建议升级 32GB。
- **v2 视觉为 2D 写实 talking-head**：基于 Wan2.2 底版视频 + wav2lip 实时口型，不是 3D；头部与上身动作受底版视频限制，口型与真人 3D 有差距。
- **表情驱动能力有限**：wav2lip 主要做音频驱动口型；原始需求中的情绪标签在 v2 中主要影响文案语气与后台逻辑，表情映射能力有限，属后续增强项。
- **交互为「点击语音球说话」**：非全天候免唤醒；静音检测与打断依赖 VAD 参数调优。
- **音色克隆质量依赖参考音频**：需 5-15 秒清晰单人声；参考音频噪声或语速异常会降低克隆质量与听感。
- **Gradio 前端为基线形态**：视觉定制与组件扩展能力有限，升级自定义前端留待后续版本。
- **首次下载体积大**：含大模型、Wan2.2、ASR/TTS 模型等，需联网且磁盘预留足够空间。
- **单用户单角色单会话**：无长期记忆与多角色管理。
- **WebRTC 推送受网络环境影响**：本机 localhost 为最佳场景；跨 WLAN 可能抖动。
- **换角色成本**：更换数字人需重新用 ComfyUI + Wan2.2 生成 `idle.mp4` 底版（一次性操作，耗时耗显存），并确保底版嘴部闭合以利于 wav2lip 驱动。
