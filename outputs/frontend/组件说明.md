# 前端组件说明 — local-ai-companion-v2

> 本文档说明 Gradio UI 的组件布局、交互逻辑、状态机驱动的 UI 行为、WebRTC 视频嵌入方式及连接状态提示逻辑。
>
> 前端基于 Gradio 4.x 框架，页面在 `outputs/backend/app.py` 的 `create_ui()` 函数中定义。

## 2. 组件清单与交互逻辑

### 2.1 数字人画面区域

- **组件**: `gr.HTML` (avatar_video)
- **位置**: 页面顶部，居中
- **默认内容**: 静态占位 HTML —— 显示图标 + "数字人待机中..." + "启动 LiveTalking 后自动接入画面" 提示
- **LiveTalking 接入后**: 替换为 `<video>` 标签，通过 WebRTC 接收 wav2lip256 实时口型视频流
- **CSS**: `.avatar-container` — 最大宽度 720px，宽高比 704:896，圆角 16px，暗色背景，带阴影
- **WebRTC 嵌入方式**:
  1. 浏览器通过 avatar-sync.js (:8011) 的 WebSocket `/ws` 建立信令连接
  2. avatar-sync.js 作为信令代理，中继 LiveTalking (:8010) 的 SDP offer/answer 和 ICE candidate
  3. 前端 JavaScript（在 Gradio 自定义 JS 中）创建 RTCPeerConnection，接收视频流后绑定到 `<video>` 元素
  4. 视频自动播放（autoplay + playsinline），muted 属性避免音频回环

### 2.2 语音球按钮

- **组件**: `gr.Button` (voice_btn)
- **样式**: 圆形按钮（80×80px），中间显示麦克风图标 &#x1F399;
- **交互**: 点击触发 `/麦克风` Accordion 展开，用户在 Gradio 音频组件中录制或上传音频
- **CSS 动画**: `.voice-ball-btn.recording` — 录音时 pulse 动画（1.5s 周期缩放呼吸效果 + 红色阴影光晕）
- **状态联动**: 录音时 Gradio 音频组件的 `.stop_recording()` 事件触发语音管线

### 2.3 停止按钮

- **组件**: `gr.Button` (stop_btn)
- **样式**: variant="stop"（红色），显示停止图标 &#x23F9;
- **交互**: 点击 → `handle_stop()` → `pipeline.stop()` → 取消令牌设置
- **效果**: 终止 LLM 流、TTS 队列、音频播放；状态机回到 IDLE
- **验收**: 音频与口型在 ≤500ms 内停止（架构设计 R6 打断串音缓解）

### 2.4 聊天记录

- **组件**: `gr.Chatbot` (chatbot)
- **高度**: 350px，内部可滚动
- **内容**: 用户消息左对齐（或按 Gradio 默认格式），AI 消息右对齐
- **流式展示**: 通过 generator yield 逐步更新 chatbot 内容
  - 用户消息填入后立即显示
  - AI 回复 token 逐段追加，最后一条消息实时变化（`chat_history[-1] = [user, reply_buffer]`）
- **Markdown 渲染**: Gradio Chatbot 使用 Markdown 渲染消息内容（SEC-04: 默认安全转义 HTML）
- **角色标签**: 自动显示 "You"（用户）和 "Assistant"（AI）

### 2.5 文字输入框

- **组件**: `gr.Textbox` (text_input)
- **占位符**: "输入文字消息..."
- **交互**: 按 Enter 或点击「发送」按钮 → `handle_text_input()`
- **US-06 文字兜底**: 不依赖麦克风/ASR，文字直接送入 LLM 转发 → 流式回复 → 可选 TTS

### 2.6 发送按钮

- **组件**: `gr.Button` (send_btn)
- **交互**: 同文字输入框的 submit 事件

### 2.7 麦克风音频组件

- **组件**: `gr.Audio` (audio_input)
- **折叠**: 放在 Accordion "麦克风（上传录音）" 内，默认收起
- **来源**: `sources=["microphone", "upload"]` — 支持实时录音和文件上传
- **类型**: `type="numpy"` — 返回 (sample_rate, numpy_array) 元组
- **事件**: `.stop_recording()` → `handle_audio_input()` → 语音管线全链路

### 2.8 参考音频上传（音色克隆）

- **组件**: `gr.Audio` (ref_audio_upload)
- **折叠**: 放在 Accordion "音色克隆设置" 内，默认收起
- **来源**: `sources=["upload"]` — 仅文件上传，不录音
- **类型**: `type="filepath"` — 返回文件路径字符串
- **约束**: 5-15秒，wav/mp3/m4a/flac，最大15MB（SEC-12）
- **反馈**: upload_status Textbox 显示上传结果（成功/失败+原因）

### 2.9 连接状态提示

- **组件**: `gr.HTML` (connection_html) + `gr.Textbox` (status_text)
- **内容**: HTML 内联渲染 5 个服务状态点 + 文字标签
- **逐服务点亮逻辑**:
  ```
  大模型 (llama:8090):   GET /health → 200 → 绿色/connected  | 其他 → 红色/disconnected
  语音识别 (ASR):        本地进程内 → 始终绿色/ready
  语音合成 (TTS):        本地进程内 → 始终绿色/ready
  数字人口型 (:8010):    GET /health → 200 → 绿色/connected  | 其他 → 红色/disconnected
  画面桥接 (:8011):      GET /health → 200 → 绿色/connected  | 其他 → 红色/disconnected
  ```
- **颜色约定**:
  - 绿色 (connected/ready): 服务正常
  - 黄色 (degraded/timeout): 服务响应异常
  - 红色 (disconnected/error): 服务未启动或不可达
- **刷新方式**: 点击「刷新连接状态」按钮手动刷新；页面初始加载时自动刷新一次

### 2.10 工具快捷按钮与浮层

- **位置**: 页面左下角固定快捷按钮组，不参与主布局尺寸计算。
- **按钮**: 「设置」「日志」「状态」，使用统一 SVG 图标、文字标签和可见键盘焦点。
- **设置面板**: 展示经过脱敏的 LLM/VoxCPM/播放配置；参考音频和参考文本通过「应用设置」显式提交，失败时保留当前音色。
- **日志面板**: 只读取固定白名单中的应用、VoxCPM、数字人、桥接日志，默认显示最近 200 行；支持服务筛选和手动刷新，不提供任意路径读取或清空日志。
- **状态面板**: 复用 `get_service_status()` 显示 LLM、ASR、TTS、LiveTalking、avatar-sync 的文字状态；打开或点击刷新时探活，不做全局轮询。
- **浮层行为**: 设置、日志、状态互斥显示；点击「关闭」或按 `Esc` 收起，使用 fixed overlay 不改变聊天区、数字人区和输入区布局。

## 3. 状态机驱动的 UI 行为

数字人状态机 (AvatarStateMachine) 的 4 个状态驱动以下 UI 变化：

| 状态 | 中文显示 | UI 变化 |
| --- | --- | --- |
| IDLE（待机） | "待机" | 数字人画面显示待机动画；语音球可点击；停止按钮灰色 |
| LISTENING（倾听） | "倾听中..." | 数字人画面显示倾听表情；语音球 pulse 动画；麦克风采集指示灯亮 |
| THINKING（思考） | "思考中..." | 数字人画面显示思考动画；语音球不可点击；停止按钮可点击 |
| SPEAKING（说话） | "说话中..." | 数字人画面显示说话嘴型；语音球不可点击；流式回复在 chatbot 实时更新 |

**状态流转触发**:
- 用户点击语音球/开始录音 → IDLE → LISTENING
- 录音结束（stop_recording）/ VAD 检测句尾 → LISTENING → THINKING
- LLM 首句文本就绪送 TTS → THINKING → SPEAKING
- TTS 播放完毕 / LLM 流结束 → SPEAKING → IDLE
- 用户点击停止 / 重新开始录音（打断）→ 任意状态 → IDLE（最高优先级）

## 4. WebRTC 视频嵌入方式

### 4.1 架构

```
浏览器                              avatar-sync.js (:8011)          LiveTalking (:8010)
  |                                        |                              |
  |-- WebSocket /ws ----> 信令中继 ------> WebSocket /ws -->              |
  |    (SDP offer/answer, ICE)             |                              |
  |                                        |                              |
  |<-- WebRTC 视频流 <---------------------| <-- wav2lip256 视频帧 -------|
```

### 4.2 前端 JavaScript（自定义注入）

由于 Gradio 组件层不直接支持 WebRTC，需要在 Gradio 的 `head` 参数中注入自定义 JavaScript 或通过 `gr.HTML` 嵌入 `<script>` 标签：

```html
<script>
// 建立 WebRTC 连接
const ws = new WebSocket('ws://localhost:8011/ws');
const pc = new RTCPeerConnection({
    iceServers: [{ urls: 'stun:stun.l.google.com:19302' }]
});

// 接收远程视频流
pc.ontrack = (event) => {
    const videoEl = document.querySelector('.avatar-container video');
    if (videoEl) {
        videoEl.srcObject = event.streams[0];
    }
};

// 信令交换
ws.onmessage = async (event) => {
    const msg = JSON.parse(event.data);
    if (msg.type === 'offer') {
        await pc.setRemoteDescription(new RTCSessionDescription(msg));
        const answer = await pc.createAnswer();
        await pc.setLocalDescription(answer);
        ws.send(JSON.stringify(answer));
    } else if (msg.type === 'candidate') {
        await pc.addIceCandidate(new RTCIceCandidate(msg.candidate));
    }
};

pc.onicecandidate = (event) => {
    if (event.candidate) {
        ws.send(JSON.stringify({ type: 'candidate', candidate: event.candidate }));
    }
};
</script>
```

### 4.3 待机画面

当 LiveTalking 未启动或 WebRTC 未连接时，avatar_video 显示静态占位内容（图标 + 提示文字）。

## 5. 连接状态提示逻辑

### 5.1 探测频率

- 页面加载时：自动探测一次
- 手动刷新：点击「刷新连接状态」按钮
- 语音/文字事件触发时：不自动刷新（避免频繁 HTTP 请求）

### 5.2 探活实现

`get_service_status()` (app.py) → 对各服务 URL 发起 GET /health 请求：

```python
{
    "llama":        check_service("llama-server", "http://localhost:8090/health"),
    "asr":          "ready",  # 本地进程内，始终就绪
    "tts":          "ready",  # 本地进程内，始终就绪
    "livetalking":  check_service("LiveTalking",  "http://localhost:8010/health"),
    "avatar_sync":  check_service("avatar-sync",  "http://localhost:8011/health"),
}
```

### 5.3 渲染

`update_connection_status()` → 生成 HTML 字符串，每个服务一行，包含颜色圆点 + 服务名 + 状态文字。

- 音频播放控制（Gradio 内置处理，无需自定义 JS）

## 7. 与 API 契约的对应

| 前端功能 | 触发 | 后端接口 | 契约章节 |

| 页面加载 | 浏览器 GET / | Gradio 自动渲染 | API §4.1 |

| 连接状态 | 手动刷新 | get_service_status() | API §9 |
