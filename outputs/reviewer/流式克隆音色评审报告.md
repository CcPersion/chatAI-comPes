# 流式克隆音色代码评审

## 结论

**通过，带一个环境级警告**：实现符合本地运行、克隆音色、不限制回复长度和单用户会话约束；未发现新的致命安全问题。麦克风自动化验收受浏览器权限限制，不能据此声称语音输入已完成本轮浏览器验收。

## 审查范围

- `outputs/backend/app.py`
- `config/voice.yaml`
- `scripts/avatar-embed.html`
- `scripts/start-livetalking.sh`

## 关键检查

1. `TTSEngine` 缓存 `voice_clone_prompt`，默认 `TTS_BACKEND: qwen`，每个回复只生成音频，不重复构建参考音色特征。
2. `pop_tts_units()` 只改变 TTS 提交边界，不限制 `full_reply`；完整回复仍写入对话历史。
3. 口型缓冲在音频事件 yield 前写入，避免单句回复出现“声音有、嘴不动”。文本分段使用同步转发，避免下一次 GPU 合成抢跑。
4. LiveTalking `humanaudio` 返回体现在 HTTP 200 下也会校验 `code`，并对 `session not found` 做有限重试，避免把业务失败误报成成功。
5. iframe 删除外层重复占位层，使用版本参数加载重连脚本；`/is_speaking` 探活和 WebRTC 状态轮询用于发现过期会话。
6. 启动脚本不再探测不存在的 `/health`，改用真实存在的 `/avatar-embed.html` 作为就绪探针。
7. 未引入 `eval`、动态 shell 拼接、用户输入命令执行、SQL 或硬编码密钥；新增 HTTP 请求目标仍来自配置或固定本地 LiveTalking 路径。

## 保留意见

Qwen3-TTS 1.7B 当前 Python 接口仍然是非流式音频数组生成；本次实现显著减少“等完整回复后才开始播放”的等待，但不应把它描述为真正的 150ms 音频首包或完整 Realtime TTS。若继续追求秒级体验，应单独评估 Fun-CosyVoice3 等本地流式后端，不应在本次改动中偷偷替换克隆音色。
