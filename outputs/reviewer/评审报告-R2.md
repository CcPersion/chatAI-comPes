### P0-1: cancel_event 状态机逻辑错误 (旧 L176-186)

- **R1 问题**: `transition()` 进入 LISTENING 时无条件 set cancel_event，IDLE→LISTENING 正常流程触发 cancel，LLM 流式回复被立即中断，语音管线完全失效。
- **声称修复**: L203 增加 old_state 判定。
- **验证结果**: ✅ 已修复
- **验证详情**:
  - app.py L197-208（transition 方法）:
    ```python
    if new_state in (AvatarState.LISTENING, AvatarState.IDLE) and old_state in (AvatarState.SPEAKING, AvatarState.THINKING):
        self._cancel_event.set()
    ```
  - **IDLE→LISTENING（正常开始对话）**: `new_state=LISTENING` in (LISTENING, IDLE) = True, `old_state=IDLE` in (SPEAKING, THINKING) = **False** → cancel **不触发**。修复正确。
  - **SPEAKING→LISTENING（打断）**: `new_state=LISTENING` in (LISTENING, IDLE) = True, `old_state=SPEAKING` in (SPEAKING, THINKING) = **True** → cancel **触发**。打断功能保留。
  - **THINKING→IDLE（用户停止）**: `new_state=IDLE` in (LISTENING, IDLE) = True, `old_state=THINKING` in (SPEAKING, THINKING) = **True** → cancel **触发**。停止功能保留。
  - **process_voice() 全流程验证** (L842-922):
    ```
    L848: reset_cancel()            → cancel_event.clear()
    L851: transition(LISTENING)     → old=IDLE, 不触发 cancel ✓
    L855: transition(THINKING)      → new=THINKING, 不匹配条件 ✓
    L876: stream_chat(cancel)       → cancel_event.is_set() == False → 正常流式 ✓
    ```
  - LLM streaming 流程不再过早中断，语音管线可以正常产生对话回复。修复完整且正确。

### Bug-006: voice.yaml 中 LOG_LEVEL 和 LOG_DIR 未被读取

- **R1 问题**: `app.py` L41-44 `logging.basicConfig` 硬编码，未读取 `voice.yaml` L87/L91 的日志配置。
- **声称修复**: 读取 LOG_LEVEL / LOG_DIR 并应用到 logger 配置。
- **验证结果**: ✅ 已修复
- **验证详情**:
  - app.py L135-151:
    ```python
    LOG_LEVEL = str(config.get("LOG_LEVEL", "INFO")).upper()
    LOG_DIR = os.path.expanduser(str(config.get("LOG_DIR", "~/setup/logs")))

    _log_level = getattr(logging, LOG_LEVEL, logging.INFO)
    os.makedirs(LOG_DIR, exist_ok=True)
    _log_file = os.path.join(LOG_DIR, "voice-pipeline.log")

    _root_logger = logging.getLogger()
    _root_logger.setLevel(_log_level)
    try:
        _fh = logging.FileHandler(_log_file, encoding="utf-8")
        _fh.setFormatter(logging.Formatter('[...]'))
        _root_logger.addHandler(_fh)
    except Exception as _e:
        logger.warning(...)
    ```
  - `getattr(logging, LOG_LEVEL, logging.INFO)` 安全地将字符串转为 logging 级别常量（SEC-02: 非 eval，使用 getattr 安全）。异常处理兜底，文件日志创建失败时仅警告不中断启动。
  - 注意: `logging.basicConfig` (L41-44) 仍保留在模块顶层，但 L143 的 `_root_logger.setLevel(_log_level)` 会覆盖其级别。FileHandler 被追加到 root logger。两者并存无冲突，但 root logger 上同时存在 StreamHandler 和 FileHandler，日志会同时输出到控制台和文件——这是合理行为。
