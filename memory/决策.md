# 关键决策: local-ai-companion-v2

## 架构决策

1. **技术栈固定（零度方案）**: llama.cpp + faster-whisper + Qwen3-TTS + wav2lip256 + LiveTalking + Gradio。不做新选型，只做组件拼图。
   - **Why**: 零度解说 2026-08-03 已验证可运行，降低风险
   - **何时重审**: 如 Gradio 定制无法满足用户体验，可升级 React 前端

2. **llama-server 放 Windows 侧**: 而非全部放进 WSL2
   - **Why**: GPU 直通更稳定，CUDA 驱动兼容性好
   - **风险**: WSL2 ↔ Windows 跨系统通信增加延迟，需 127.0.0.1 绑定 + localhostForwarding

## 流程决策

3. **standard + minimal 档位**: 快速原型模式，门禁只查文件存在，评审只做正确性维度
   - **Why**: 项目处于早期原型阶段，代码无法实际运行（需 WSL2 + GPU），过重流程无意义
   - **代价**: 安全深度审查不足，正式发布前建议切换 strict 档位重审

4. **Reviewer R1 驳回后一轮修复通过**: cancel_event 逻辑错误是唯一真正的阻塞 bug，修复后正确性从 55→90
   - **教训**: 状态机的取消信号触发条件必须精确，正常流程和打断流程需要区分
   - **模式**: `transition()` 中 cancel_event 只在打断场景（活跃→停止）触发

## 产出质量

5. **3,200+ 行代码、28 测试用例、8 缺陷修复**: 标准流水线 5 角色全部参与
   - PM/Architect/Developer/QA/Reviewer 各尽其职
   - 安全自检嵌入代码（SEC-02~20 逐模块标注）
   - R1→R2 返工一次即通过，符合 minimal profile 1轮上限
